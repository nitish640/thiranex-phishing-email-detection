# Phishing Email Detection Model

**Thiranex Cyber Security Internship — Task 3** (due 14 Jul 2026)
Build a machine-learning model using Scikit-learn that trains on phishing
and legitimate emails, extracts URL / keyword features, classifies emails as
**"Phishing"** or **"Safe"**, and displays accuracy and a confusion matrix.

## What was built

- **Model:** TF-IDF (subject + body, 1–2 grams, 2,000 features) +
  14 hand-crafted numeric features → **Logistic Regression**
  (`class_weight="balanced"`, `max_iter=1000`)
- **Features extracted** (`src/features.py`): URL count, suspicious-keyword
  count, urgency-word count, raw-IP URL, link shortener, suspicious free
  TLD (.ru/.xyz/.top), sender-domain vs link-domain mismatch, link/text
  mismatch (`click here` + link), plain-http link, digit in sender domain
  (look-alike brands like `paypa1`), exclamation count, `$` amount,
  body length, URL length
- **Dataset:** `data/emails.csv` — **500 emails, balanced 250 phishing /
  250 safe**, columns `label, subject, sender, body, url`.
  The dataset is **synthetic but realistic**, generated by
  `src/generate_dataset.py` from phishing patterns (account-suspension
  threats, prize lures, fake bank/delivery notices, mismatched senders,
  IP/shortened URLs) and legitimate patterns (meetings, orders,
  newsletters, HR mail). It is documented as synthetic training data —
  **no real emails or personal data were used**.
- **Predictor:** `src/predict.py` — CLI, prints label, phishing
  probability and the top reasons (e.g. "sender domain does not match
  the link domain")
- **Web UI:** `app.py` — stdlib-only, paste an email and get
  Phishing/Safe with confidence and reasons

|---|---|---|

**Honest caveat:** 100% is on the synthetic held-out set. The synthetic
phishing and safe templates use very distinct wording, so the task is
easier than on real mail — on a real-world dataset (e.g. the public
Phishing Email dataset on Kaggle / the Nazario + SpamAssassin corpora)
accuracy would be lower, typically 90–97% for this kind of model.
The value here is the full pipeline — feature extraction, TF-IDF +
numeric features, train/test evaluation, saved model, and a usable
predictor — not the 100% number. Full metrics are in
`models/metrics.json` (regenerated by training).

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## How to run

```bash
# 1. (Re)generate the dataset — 500 rows, balanced
python src/generate_dataset.py

# 2. Train and evaluate (saves models/phishing_model.joblib + models/metrics.json)
python src/train.py

# 3. Predict from the command line
python src/predict.py --demo
python src/predict.py --subject "Urgent: verify your account" \
  --sender "support@paypa1-secure.com" \
  --body "Click the link to verify your identity immediately." \
  --url "http://paypa1-secure.com/login"

# 4. Web UI
python app.py
# open http://localhost:8000
```

## What was learned

- Phishing is betrayed as much by **structure** as by words: mismatched
  sender/link domains, raw-IP and shortened URLs, plain http, and
  look-alike domains (`paypa1`, `amaz0n`) are strong signals that
  survive even when the wording is polished.
- **Urgency language** ("within 24 hours", "account will be suspended")
  is the most consistent textual signal across phishing templates.
- Combining **TF-IDF text features with hand-crafted numeric features**
  beats either alone: text catches the wording, numeric features catch
  the URL tricks.
- A perfect score on synthetic data is a warning, not a victory:
  always evaluate on real, held-out data before trusting a model,
  and report precision/recall (not just accuracy) — missing a phishing
  mail (false negative) is costlier than flagging a safe one.
